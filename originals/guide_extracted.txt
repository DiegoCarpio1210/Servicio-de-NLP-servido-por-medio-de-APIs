I. Objective
Your team will fine-tune a pretrained Transformer encoder forextractive question answering
and deploy it as anaccess-controlled web servicebehind a fixed API. On presentation day, the
instructor will call your API live with a hidden test set and evaluate the responses automatically.
This is an AI engineering project. You may use AI coding agents, but you are expected to know
what your code does, what it does not do, and why.
II. Constraints
Duration:1.5 weeks.
Teams:your PBL groups (4–5 students).
Models:pretrained base encoder checkpoints only; you fine-tune them yourselves.
AI coding agents:allowed (Claude Code, Gemini, Codex, etc.).
Language:English.
Training hardware:university GPUs when available, or your own hardware.
Serving hardware:your own laptop, exposed through a public tunnel (Section IX). Plan for
CPU-only inference.
Latency:not graded, but a per-request timeout and a global time cap apply (Section XII).
III. Task
Extractive question answering with unanswerable questions (SQuAD 2.0 style). Given a context
paragraph and a question, your service returns the answer as a span of the context, orno answer if the
context does not contain it.

IV. Models
Choose one encoder and justify your choice.
Family Examples Notes
Classic encoder DistilBERT, BERT-base, RoBERTa-base Laptop-CPU friendly
Modern encoder DeBERTa-v3-base, ModernBERT-base State-of-the-art encoders
Decoders (GPT-style models) are not allowedfor the implementation: they are slow on a
laptop CPU, their generated answers do not fit exact-match evaluation, and the time frame does not
allow doing both well. Decoders are covered in your report instead (Section XIII).
V. Rules
1. Start from a base checkpoint. Checkpoints already fine-tuned on SQuAD arenot allowed. Trai-
ning logs and loss curves are required.
2. No commercial API calls (OpenAI, Gemini, Anthropic, etc.). The model runs locally.
3. The service must implement the API contract (Section VII) exactly, including access control.
4. The access token must be read from an environment variable. It must never be written in code or
committed to the repository.
5. Git history must be preserved. Do not squash it into a single commit.
Submissions are checked automatically for compliance with these rules.
VI. Data
Training:SQuAD 2.0 train set (≈130k questions,≈1/3 unanswerable). You may subsample.
Public sample set:public_sample.json, 5 items in the/predictrequest format, with reference
answers and their character offsets. Two are unanswerable and one has a context longer than 512
tokens. Released with this brief for local testing and the dry run.
Hidden test set:50 questions written by the instructor on texts not taken from SQuAD,≈25%
unanswerable. It is not released.
VII. API contract
The full machine-readable contract is the OpenAPI fileqa_api_contract.yaml, distributed with
this brief. This section summarizes it. If the two disagree, the YAML file prevails.

VII.1. General rules
Base URL:the public HTTPS URL of your tunnel (Section IX). Locally, the service listens on
port8000.
Format:all bodies are JSON, UTF-8, with headerContent-Type: application/json.
Authentication:protected endpoints require the headerAuthorization: Bearer <token>. The
service reads the token from the environment variableQA_API_TOKEN. Comparison is exact and
case-sensitive.
Errors:every error response has this body:
{"error": "<code>", "detail": "<optional text>"}
where<code>isunauthorized,bad_requestorinternal_error, anddetailis optional.
Timeout:the harness waits at most 5s per request.
Extrafieldsinyourresponsesareallowedandignored.Amissingrequiredfieldmakestheresponse
invalid.
Endpoint Method Auth Success Error codes
/healthGET Public 200 503 while the model is loading
/infoGET Protected 200 401
/predictPOST Protected 200 400 or 422 (invalid body), 401, 500

VIII. Access control
Your service validates the bearer token on/infoand/predict, and returns401for a missing or
invalid token./healthstays public.
Adevelopment tokenis distributed with this brief, for development and the dry run.
Adifferent tokenis given on presentation day. You set it inQA_API_TOKENbefore the evaluation
starts.
Access control is checked automatically at the dry run and on presentation day.
IX. Network setup: public tunnel
Your service runs on a team member’s laptop. The instructor’s harness reaches it through apublic
HTTPS URLcreated with a tunnel tool. This does not depend on the classroom Wi-Fi or on university
network policies: the laptop only needs internet access.
The URL is public, so anyone on the internet can call your service. This is why access control
(Section VIII) matters.

Live evaluation
The harness sends the 50 hidden items one at a time.
Per-request timeout:5s. Global cap:150s. Items not answered by the cap count as failed.
Exact Match and F1 are shown live. Answers that partially overlap the reference are assessed by
an automated LLM judge; that part of the score may be finalized after the session.
Network

instructor before your slot.
